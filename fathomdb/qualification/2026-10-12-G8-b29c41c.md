**Baseline-vs-`C` differences, explained against the maps.** The baseline
tries unversioned names first, so with only a venv `cublas/lib` directory on
`LD_LIBRARY_PATH` (which holds no unversioned name):

- a and b: `libcublas.so` resolves through the loader cache to the system
  **12.6** `libcublas.so.12.6.1.4`, and the process ends up with **two**
  cuBLASLt copies: the baseline maps (a, `cu12-124` and `cu12-129`) list the
  venv `libcublasLt.so.12`, the system `libcublasLt.so.12.6.1.4` and the
  system `libcublas.so.12.6.1.4`. (How each cuBLASLt copy was reached, by
  `dlopen` or as a dependency, is not separated by the maps.) That mixed set
  fails `asum` with 12.9.2 and crashes with 12.1.3 (no maps: the process died
  before exit); with 12.4.5 it happens to pass. The baseline therefore
  never tested the venv's cuBLAS on its own.
- c: the 13000 baseline build loads the system **12.6** cuBLAS and cuBLASLt
  (cross-major), and passes.
- `C` opens the built major's versioned names first (`libcublas.so.12`,
  `libcublas.so.13`), finds the venv's files, and the report and maps name
  them (below). This is the item-9 behaviour CF-REQ-11 requires.
